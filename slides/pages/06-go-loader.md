# Phase 1: Preparing System Resources (rlimit)

Before loading any eBPF code, we must adjust the lockable memory limits on older kernels.

```go
func main() {
    // Remove resource limits for kernels <5.11.
    if err := rlimit.RemoveMemlock(); err != nil {
        log.Fatal("Removing memlock:", err)
    }
    
    // ...
}
```

<div class="grid grid-cols-2 gap-8 mt-4 text-sm">
<div class="hl hl-blue">

**What is Memlock?**
* Historically, the Linux kernel restricted the amount of memory a non-root process could lock into RAM (`RLIMIT_MEMLOCK`).
* Since BPF maps are locked in kernel memory, loading maps would fail if they exceeded this limit.

</div>
<div class="hl hl-green">

**Modern Linux Kernels (5.11+)**
* Modern kernels use cgroups to track memory overhead for BPF, making memlock adjustments obsolete.
* However, keeping `rlimit.RemoveMemlock()` ensures your Go agent is backward-compatible with older systems.

</div>
</div>

<!--
The first step in `main.go` is calling `rlimit.RemoveMemlock()`.
Historically, the kernel had strict limits on how much memory a process could lock in RAM. Since BPF maps live in pinned kernel memory, they count against this "locked memory limit".
Calling this function lifts those limits.
In modern kernels (5.11 and newer), BPF memory usage is tracked via control groups (cgroups), so this is no longer strictly necessary. However, including it is a best practice to ensure your agent runs on older kernels.

# Phase 2: Loading eBPF Objects into the Kernel

`bpf2go` generated the code to load our compiled ELF objects. We initialize them with a single function call:

```go
    // Load the compiled eBPF ELF and load it into the kernel.
    var objs counterObjects
    if err := loadCounterObjects(&objs, nil); err != nil {
        log.Fatal("Loading eBPF objects:", err)
    }
    defer objs.Close()
```

<div class="grid grid-cols-2 gap-8 mt-4 text-xs">
<div class="card card-purple">
<p class="font-bold text-slate-800">`counterObjects` Struct</p>
<p class="text-slate-600 mt-1">Generated by <code>bpf2go</code>, it aggregates all programs and maps defined in the C code:</p>
<pre class="bg-slate-900 text-slate-100 p-2 rounded mt-2">
type counterObjects struct {
    counterPrograms
    counterMaps
}
</pre>
</div>
<div class="hl hl-slate">

**What `loadCounterObjects` does:**
1. Reads the compiled BPF bytecode (embedded inside the Go binary).
2. Performs the `bpf()` system call to load the bytecode.
3. The kernel runs the Verifier and compiles it using JIT.
4. Returns handles to the loaded maps and programs, populated inside `objs`.

</div>
</div>

<!--
The second phase is loading the compiled eBPF objects.
`counterObjects` is a struct generated for us by `bpf2go`.

We also make sure to defer `objs.Close()` to release these handles when our program exits.

# Phase 3: Attaching to the Network Interface (XDP)

To make our program execute on incoming traffic, we must attach it to a network interface using the Link package.

```go
    ifname := "eth0" // Change this to an interface on your machine.
    iface, err := net.InterfaceByName(ifname)
    if err != nil {
        log.Fatalf("Getting interface %s: %s", ifname, err)
    }

    // Attach count_packets to the network interface.
    link, err := link.AttachXDP(link.XDPOptions{
        Program:   objs.CountPackets,
        Interface: iface.Index,
    })
    if err != nil {
        log.Fatal("Attaching XDP:", err)
    }
    defer link.Close()
```

<!--
The third phase is attaching our program to a specific hook.
We find the target network interface by name, for example `eth0`.
Then, we call `link.AttachXDP()`.
We pass it two options:
1. The program we want to run, which is `objs.CountPackets` (matching our C function name, capitalized by `bpf2go`).
2. The network interface index.
Once this call succeeds, the kernel attaches our program to the driver of that network card. Every packet arriving on `eth0` will now trigger our C code!
We also defer `link.Close()`, which will detach the program when the userspace process is stopped.

# Phase 4: Reading Map Data in Go

Now that the program is running in the kernel, our Go program loops and reads the packet count from the map.

```go
    tick := time.Tick(time.Second)
    stop := make(chan os.Signal, 5)
    signal.Notify(stop, os.Interrupt)
    for {
        select {
        case <-tick:
            var count uint64
            err := objs.PktCount.Lookup(uint32(0), &count)
            if err != nil {
                log.Fatal("Map lookup:", err)
            }
            log.Printf("Received %d packets", count)
        case <-stop:
            log.Print("Received signal, exiting..")
            return
        }
    }
```

<!--
The final phase is reading the metrics.
We set up a one-second ticker and a signal channel to listen for Interrupt signals (like Ctrl+C).
Every second, we query the map.
We call `objs.PktCount.Lookup(uint32(0), &count)`.
We pass it key `0` (the only key in our map) and a pointer to a `uint64` variable.
The library executes the `bpf()` system call to fetch the value from kernel memory, storing it in `count`.
We then log it.
When we press Ctrl+C, the loop terminates, defer statements clean up the links and maps, detaching the program from the driver, and we exit cleanly.
